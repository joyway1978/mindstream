# 方案与实现评审

> 评审对象：`docs/02-design.md` 与当前实现
> 评审方式：方案红队自审 → 实现逐模块审查 → 单测 → 真实模型链路验证
> 日期：2026-11-17

## 1. 结论

**方案成立，实现可用。** 核心体验已经跑通：智能体在没有用户输入时持续思考，把想法、洞察、问题和用户事实写入 SQLite，能在一轮对话里检索旧记忆，并在门控允许时主动发消息；Web 端能实时看到思考链与对话流。

但有三件事必须说清楚：

1. **“主动”不等于“自动说话”**。实测中模型经常选择不说，这是设计允许的，也是它不像骚扰机器人的原因；代价是演示时不一定每分钟都有主动消息。
2. **持续运行有持续成本**。20 秒 tick、每 3 个 tick 反思的激进配置下，10 分钟约 3.8 万 tokens、13 次调用。默认 30 秒 / 每 6 个 tick 反思会低一些，但仍是长期支出。
3. **记忆还没有“编辑/遗忘”入口**。目前只能靠写入去重和反思压缩控制质量；用户无法删除一条错误记忆。这是 V1 最大的产品缺口。

## 2. 方案层面的红队质疑与裁决

| # | 质疑 | 裁决 | 依据 / 后续 |
| --- | --- | --- | --- |
| Q1 | 所谓“主动思考”会不会只是每 30 秒调用一次模型，把同样的上下文再说一遍？ | **部分成立，已通过状态化缓解** | 上下文包含自我模型、当前关注、开放问题、最近思考与检索记忆，不是无状态 prompt；实测模型会引用前几轮编号问题并自我修正。但没有外部观察源时，长期仍可能空转（见 Q6）。 |
| Q2 | 自动抽取记忆会把模型的推测写成用户事实，越用越脏 | **风险真实，已做三层缓解，未根治** | ① `kind` 区分 fact/preference/insight；② 写入前同 kind 相似度 >0.82 合并；③ 记忆带 `source_ids`。仍缺：人工删除/纠正、事实置信度、冲突检测。 |
| Q3 | 主动发言会变成骚扰 | **实跑后补了“连续未回应”门控** | 初版五道检查（开关/冷却/日上限/重要性/长度）；实测模型在 2/3 的 tick 主动选择沉默，但**连续 4 条未被回应的主动消息**暴露了漏洞：冷却只限速，不判断“用户是否还在听”。已增加「连续未回应上限=2」，超过即闭嘴直到用户再说话。首条主动消息曾出现内部术语（“悬置线索”），已在 prompt 中禁止，但还没有硬性“可理解性”校验。 |
| Q4 | token 成本失控 | **有界但不可忽视** | 空闲指数退避到 5 分钟、max_tokens 上限、按日用量展示、连续失败降速。实测见 §4。 |
| Q5 | 单进程 + 单思考锁，用户说话会不会被 tick 卡住 | **会等待，但通常 10–25 秒** | 对话优先级高于后台 tick；不做“打断模型”，避免半截 JSON 与状态不一致。体验上仍是风险，若 tick 变慢需要超时/取消策略。 |
| Q6 | 反思会滑向“反复分析自己怎么想”的自溺 | **实测确实发生** | 连续多个 tick 围绕“节律面板给我压力”打转，模型自己也承认空转。已加 prompt 约束（想用户的世界、洞察指向具体问题），但结构性解法是引入外部观察源（V3）。 |
| Q7 | 安全边界 | **当前较窄** | 没有工具、没有外部写入、没有浏览；用户输入只能影响对话与记忆。API key 只在 `.env`（gitignore），接口不返回 key。风险主要是隐私（用户文本落本地库）与提示注入（影响思考质量，不影响系统权限）。 |
| Q8 | 能不能复现 | **可以** | `python main.py` 一条命令；无外部数据库；`--mock` 可离线演示；30 项测试不依赖网络。 |

**方案修改记录**（相对初稿）：

- 反思触发从“累计重要性阈值”改为“每 N 个 tick”，首版更好演示；接口保留，V2 可切回。
- 增加“被抑制原因”落库与 UI 展示，让“想说但没说”可见，而不是无声丢弃。
- 检索查询只取「当前关注 + 前三个开放问题」，避免把整段上下文拼进去稀释相关性。
- 增加本地日口径，避免 UTC 用户在早上 8 点“跨天”。

## 3. 实现审查：发现并修复的问题

| # | 问题 | 严重度 | 处理 |
| --- | --- | --- | --- |
| 1 | **反思 content 为空**：推理型模型的 `reasoning_content` 计入 completion，700 token 预算被推理吃满，返回空字符串，`extract_json` 失败后静默跳过 | 高（功能静默失效） | 预算提到 1400；`LLMClient` 检测空 content 后自动翻倍预算重试（上限 3200）；反思解析失败广播错误事件并写日志 |
| 2 | **每日上限按 UTC 日期重置**，本地用户早上 8 点才“新的一天” | 中 | 新增 `local_date()` / `local_day_start_iso()`，主动消息计数、统计、用量统一按本地自然日 |
| 3 | 对话在进入流式调用前抛异常时，`thinking=True` 可能卡住 | 中 | 整个 chat 主体包进 `try/finally`，出口统一复位与广播状态 |
| 4 | 后台记忆抽取任务的存储异常可能变成“Task exception was never retrieved” | 中 | `_extract_turn` 整体包 `try/except`，仅记录日志，不影响主流程 |
| 5 | 1040px 以下出现标签栏后，布局高度仍按 100vh 计算而溢出 | 低 | 媒体查询中改为 `calc(100vh - 118px)`；窄屏另行适配 |
| 6 | 测试从 `tests.conftest` 导入时被 site-packages 的 `tests` 包遮蔽 | 低 | 改为 `from conftest import ScriptedLLM`；并加 `sys.path` 兜底 |
| 7 | 一条测试断言 `... or True` 永远为真 | 低 | 删除无效断言，保留 `access_count == 1` 的有效检查 |
| 8 | 记忆去重只按同 kind 比较，跨 kind 的重复（fact ↔ insight）仍会累积 | 中（已知限制） | 当前保留：跨 kind 语义不同，强行合并会丢信息；V2 增加冲突检测 |
| 9 | **连续未回应的主动消息**：冷却只限制频率，用户不说话时仍会每两三个 tick 追一条长消息 | 高（体验） | 新增 `count_unanswered_proactive()` 与 `MIND_PROACTIVE_MAX_UNANSWERED=2`；超过后门控返回 `unanswered`，UI 显示“上一条还没被回应”，用户说话后自然重置 |
| 10 | **第二轮对话直接 400**：历史消息把内部角色 `agent` 原样传给 OpenAI 兼容接口，接口只接受 `assistant` | 高（功能不可用） | 历史映射为 `assistant`；补回归测试，断言所有 role ∈ {system, user, assistant} 且历史里确有 assistant |

静态检查与测试：

```text
ruff check app tests main.py  → All checks passed!
python -m compileall -q app main.py → ok
pytest -q → 30 passed
```

覆盖范围：中文 tokenizer / Dice / 时间衰减 / 检索排序与访问更新 / 写入去重；thought、memory、message、question、state、stats 的 SQLite 行为；单 tick 的思考-记忆-提问-发言链路；四类发言门控；非法 JSON 降级；对话检索与后台抽取；反思更新自我模型；控制接口；HTTP 接口与静态资源；空 content 重试。

## 4. 真实链路验证

环境：支持 reasoning_content 的推理型模型，`MIND_TICK_INTERVAL=20`、`MIND_REFLECT_EVERY=3`、冷却 1 tick、重要性阈值 5（都比默认激进）。

| 指标 | 实测 |
| --- | --- |
| 对话 | 1 轮，回复约 900 字，引用了用户“做主动思考智能体、记忆用 SQLite”的事实 |
| tick | 10 次，0 次连续错误；后续多轮对话测试暴露并修复了 `agent` 角色 400 |
| 反思 | 2 次，均产出 2–3 条洞察并更新自我模型 |
| 记忆 | 22 条（含 1 条用户事实、多条 insight） |
| 开放问题 | 16 条产生，6 条仍开放（反思会关闭一部分） |
| 主动消息 | 1 条，门控放行 |
| 用量 | 13 次调用 / 37,828 tokens（约 10 分钟） |
| UI | 1512×950 截图见 `docs/screenshot.png`；无 JS console 错误 |

**质量观察**：

- 思考内容不是复述上下文，而是围绕“主动和打扰的边界”持续推进，能引用自己的前几条结论。
- 反思确实产生了更高层洞察（例如把“许可”与“触发”分开、指出零成本状态会自我膨胀）。
- 第一条主动消息虽然被放行，但包含内部术语，对用户不够友好。已加 prompt 约束；这属于“模型质量”而非“机制正确性”，未做自动评分。
- 实跑中用户在 07:34 说“我先离开一会儿”，随后它连续发了 4 条长消息；虽然每条内容都不重复，但整体仍是单方面的独白。这直接催生了「连续未回应上限」门控，也是本轮评审最有价值的产品修正。
- 反思有明显的自我指涉倾向（连续多轮谈自己的节律），模型自己能识别，但需要外部话题才能根治。

## 5. 遗留风险与未做

| 项 | 影响 | 建议 |
| --- | --- | --- |
| 无法删除/修正记忆 | 错误记忆会长期参与检索 | V2 增加记忆管理 API 与 UI，支持删除/改重要性/标记错误 |
| 无外部观察源 | 长期思考容易内卷 | V3 接入只读信息源（RSS/网页检索）与“观察任务” |
| 无用户接受度学习 | 主动频率只能靠配置 | 记录“主动消息后用户是否继续对话”，形成软反馈，仍由规则裁决 |
| 长跑未验证 | 24 小时以上的内存/成本/记忆膨胀未知 | 增加每日压缩与清理任务，做 24h soak test |
| 单进程 | 不能水平扩展 | 明确为单用户本地应用；多用户需改成服务化与每用户锁 |
| 移动端仅 CSS 适配 | 未做真机交互测试 | 用 Playwright 移动视口补交互测试 |
| 无真实模型自动化评测 | 质量回归靠人工 | 建 20 条场景的“主动消息有用率/JSON 合规率”离线评测 |

## 6. 方向切换：末日生存武器准备

2026-11-17 追加。把主动思考的使命从“泛化的主动思考实验”切换为**末日生存的武器准备**，并做成可配置 profile。

**改动**：

- 新增 `app/profile.py` 与 `profiles/doomsday.json`：使命、自我模型、兴趣、关注点、5 个种子问题、5 条内容边界。
- 身份提示词改为由 profile 生成；`rules` 同时进入思考、对话、反思与记忆抽取。
- 启动时按 `profile_id` 播种；同 profile 重启保留演化结果，换方向则重新播种。旧库备份为 `data/mind.db.pre-direction-*.bak`，新库从零开始。
- Web 右栏新增「当前方向」，头部副标题与文档标题跟随 profile。

**内容边界**：只讨论合法、可安全持有与训练的装备；不提供制造爆炸物、改装违禁武器、规避审查或伤害他人的步骤；强调水、食物、医疗、通信、社区与撤离通常比武器更决定结局。

**实测**（切换后第一个 tick + 一轮对话）：

- 对话给出了四层拆解：情景轴（威胁来源 × 时间尺度 × 能否移动）→ 四种能力（发现 / 威慑 / 存活 / 制服）→ 远程 / 近战 / 防护 / 工具的具体比较 → 误伤、储存、法律与生存系统位置。
- 独立思考产出“武器只在『威胁是有意图的人』且『撤不走』时才有作用窗口”这类判断，而不是装备清单。
- 种子问题开始被推进；前两条主动生成的开放问题分别关于「威慑 vs 制止的训练投入」与「撤离窗口何时关闭」。
- 30 项测试通过；新增 profile 加载、播种幂等、自定义方向、非法 profile 校验。

**遗留**：模型仍可能把“讨论武器”滑向参数罗列；prompt 已要求不编造参数并说明适用/失效条件，但没有硬性事实校验。profile 的 `id` 不变时不会重新播种，改方向需同时改 `id` 或换库。

## 7. 最终判断

- **值得继续用**：作为“主动思考智能体”的最小完整形态，它验证了关键假设——**连续性（记忆 + 自我模型 + 开放问题）能让模型在没有输入时产生非重复的想法**，而不仅是定时总结。
- **不适合直接当产品**：缺记忆编辑、外部观察、长跑稳定性与用户接受度机制。
- **下一步优先级**：P0 记忆管理 → P1 主动消息质量评估与反馈 → P2 外部观察源 → P3 长跑与成本优化。
